# Code review, 2026-10-03

Review of `master` at 4648ce3. Items fixed since then are listed under "Fixed since the review"; everything else in this file is still open as of PR #80 (2026-10-09).

**Scope:** all of `Assets/Scripts` (225 files, about 32k lines), plus `Assets/Planet Generator/Editor`, `Assets/Tools/Editor` and `Assets/Shaders/Editor`.

**Method:**
- The code was reviewed read-only, area by area, in six areas.
- Data ranges were checked against `Starflight Game Data.json`, and scene wiring was traced through script GUIDs wherever a finding depended on it.
- The "Checked" column records whether a finding was re-verified against the code in a second pass:
  - **yes:** the failure path holds.
  - **part:** the code holds; one downstream claim rests on the first pass only.
  - **no:** traced in the first pass only.

**Not covered:**
- Compiler warnings (the compile check passes; warnings were not collected).
- `3rd Party`.
- Scenes and prefabs, except where a finding needed them.

**Labels:**
- **CONFIRMED:** the failure path is traced in code.
- **INFERRED:** one link is unverified, and that link is named.
- **HYPOTHESIZED:** plausible but unverified.

### How the fixes were checked

On 2026-10-03 the fixes were run in a headless play-mode probe: the real Spaceflight or Starport scene, new-game data, and an in-memory save system so that no save file was touched. The probe lives in the repository under `DevTools/HeadlessProbe/` (it was added after these runs).

- **PR #3 (batch 1):** H1, H2, H3, H4, M2, M3, M4, M6, M9 and the `m_lastCommIds` fix from PR #2 passed 17 checks. M1 was verified by reading the code only.
- **PR #7 onward:** H6, M15, M13, M14, M7, M22, M24, M5, M21 and the `Viewport` fix were each run before and after the change; the bug reproduced on the old code and was gone with the fix. M8 was run after the change only, because the old class could write only to the real save folder.
- **PR #21 to #26 (batch 2):** H5, M19, H7, M12, M20 and H8 were each run before and after the change, through the real buttons or the real fire and damage methods. The design of each was decided on 2026-10-03. Where the original design notes give no number (hit points per class, the repair and treatment rates, the fuel per shot), the number is a named constant in the code.
- **PR #28 to #30 (2026-10-04):** M10, M23 and the landing messages were each run before and after the change through the real flow: into orbit, down to the surface, the Disembark and Cargo buttons, and the button controller with the stick or the fire button held for one frame.
- **PR #32 (2026-10-04):** the missile fix was run before and after in both directions (an alien missile and a player missile in the air when the player leaves), together with a check that missiles still hit within their own encounter.
- **PR #33 to #42 (2026-10-04):** M11, M18, M17, M16, the landing on a planet without maps, M25 and M26 were each run before and after the change with a dedicated scenario (`m11`, `m18`, `m17`, `m16`, `nomaps`, `m25`, `m26`), all of which are in the probe in the repository.
  - M25 was run on a black map with single white pixels, which shows exactly what each neighbour contributes. The effect on a real planet was measured by comparing the albedo map of planet 90 pixel by pixel between the two runs.
  - M26 is editor code. Its scenario runs the tool's own methods by reflection on the source images of all 811 planets and compares the result with the planet files: the unchanged tool rebuilds every file's prepared height map exactly, while the fixed one differs in the south pole rows of 273 planets and nowhere else.
  - M18 was measured from a coroutine while a planet was being processed: 5 frames for 5 planets before, more than 1000 after.
  - M17 was run with eight kinds of bad file built in memory from a real one, and with one of them given to a planet of the real star system. All 811 planet files in the project pass the stricter reader.
  - M16 was flown through four star system changes: textures created at runtime went from 22 MB to 69 MB before the fix and stayed at 22 MB after it. The probe has no graphics device, so graphics memory is not included in those numbers.
  - The full set of 24 scenarios was run on the final tree.
  - Since M18 the probe waits for the first star system's planets before it starts a scenario (PR #38). Before that, scenarios started while the game was still paused for generation, and two of them reported numbers that were too low.

Of PR #57 only `PG_Tools` and `SFShaderGUI` could be run; the other editor tools sit behind dialogs and `OnGUI`.
